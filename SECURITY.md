# Security policy

## Reporting a vulnerability

Do not put secrets, personal data, exploit details, or active credentials in a public issue or pull request. If this repository's Security tab offers **Report a vulnerability**, use that private GitHub reporting flow. This document does not enable that feature or assert that it is available.

If GitHub private reporting is unavailable, email [ynginkim@gmail.com](mailto:ynginkim@gmail.com). This is the owner-designated private security reporting contact, not a GitHub login or commit identity. Do not include live credentials.

## Scope

Report unsafe handling of API keys or environment variables, secrets in logs, unexpected shell execution, writes outside the requested workspace, unsafe installation paths, and dependency vulnerabilities affecting this repository. Include the affected commit, a minimal redacted reproduction, impact, and any mitigation. Never send live credentials.

## Supported versions and expectations

No supported-release matrix or fixed response SLA has been established. Until versioned releases are published, identify the exact commit being used. Fix availability and disclosure timing are decided per report; this file makes no guaranteed response or remediation commitment. Review third-party dependency advisories separately.
